# Core: Share Permission (Resource)

Manages the complete `SYNO.Core.Share.Permission` list for one share and one `user_group_type` (all local-user grants, or all local-group grants, on that share -- never both from the same resource instance).

**Full ownership.** Every apply overwrites the declared side's permission list to exactly the `permission` blocks in config. Any row added out-of-band -- DSM Control Panel, another tool, an operator -- is treated as drift and removed on the next apply. This mirrors how `synology_core_firewall_profile` already owns its full rule set in this provider: a resource that only reconciled the rows it happened to declare could never express "revoke a grant someone else added," and two writers of the same share's permissions could drift forever with no single source of truth. Declare every row you want to exist; nothing else survives an apply.

**The `administrators` local group is not manageable here.** DSM grants it read/write on every share unconditionally and offers no way to revoke it -- it is excluded from state on every read and rejected if declared in config, so this resource never plans a change it cannot converge.

**`is_admin` is read-only.** It reflects DSM's own admin-group flag on the row, not a settable grant; it cannot be supplied in config.

**Deny vs. no access.** `is_deny = true` is an explicit deny entry, distinct from a row with every flag false (no access granted, no explicit deny either).
